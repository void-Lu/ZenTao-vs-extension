# 禅道详情页展示变更设计

## 背景与目标

当前扩展已经能在 VS Code Webview 中展示禅道需求和任务详情，并支持附件下载、富文本图片预览、Markdown 导出和原始响应折叠查看。本次变更聚焦详情页展示体验，目标是让基础信息格式更一致，让详情页内的关联对象可直接跳转，并补充页内搜索和附件预览入口。

## 范围

### 本次包含

- 优化详情页基础信息显示：
  - `进度` 统一显示百分号。
  - `最初预计`、`总计消耗`、`预计剩余`、`预计工时` 统一显示小时单位 `h`，已有单位时不重复追加。
  - 日期时间类字段统一格式化为 `yyyy-mm-dd hh:mm:ss`。
- `相关研发需求` 支持点击打开对应需求详情。
- `关联任务` 支持点击打开对应任务详情。
- 详情页支持 `Ctrl+F` / `Cmd+F` 文本匹配。
- 附件表增加 `预览` 超链接，点击后在 VS Code 内新开附件预览 Webview 面板。
- 附件大小统一换算并显示为 `K`。

### 本次不包含

- 不改变禅道数据读取 API。
- 不增加需求、任务、附件的写操作。
- 不改变现有附件下载入口含义。
- 不在系统浏览器中打开附件预览。
- 不支持附件正文内容的复杂解析；预览面板先展示附件元信息和可用链接。

## 设计方案

采用“映射层统一格式化 + Webview 渲染交互 + DetailPanel 受控消息处理”的方案。

- `detailMapper.ts` 负责把原始响应转换为最终展示模型：单位、日期时间、附件大小和关联对象都在这里归一化。
- `html.ts` 只负责根据展示模型生成安全 HTML，并处理页面内搜索、链接点击和附件预览消息。
- `detailPanel.ts` 负责接收 Webview 消息；详情跳转通过构造参数注入的回调交给 `extension.ts` 复用现有 `openDetail` 流程，附件预览则由 `DetailPanel` 创建预览面板。

这种方案能避免在 HTML 模板中散落字段判断，也延续当前 Webview CSP、nonce、消息校验和富文本清洗的安全边界。

## 基本信息格式化

### 百分比

`进度` 字段从原始响应读取 `progress`：

- 空值显示 `暂无`。
- 已含 `%` 时保持原值。
- 未含 `%` 时追加 `%`。

### 工时单位

以下字段统一通过小时单位格式化：

- 故事页：`预计工时`。
- 任务页：`最初预计`、`总计消耗`、`预计剩余`。

规则：

- 空值显示 `暂无`。
- 已含单位时保持原值，不重复追加。
- 未含单位时追加 `h`。
- 识别现有单位包括 `h`、`H`、`工时`、`小时`。

### 日期时间

所有详情页基础信息、附件和历史记录中可解析的日期时间值统一输出为 `yyyy-mm-dd hh:mm:ss`。

规则：

- 空值显示 `暂无` 或沿用当前字段已有空态。
- 可解析的日期时间字符串进行格式化。
- 只有日期、没有时间的值补为 `00:00:00`。
- 无法解析的非空值保持原值，避免误删接口返回的信息。

## 关联对象跳转

### 展示模型

`BasicField` 扩展可选链接信息。单链接字段使用：

- `linkType: 'story' | 'task'`
- `linkId: number`

多链接字段使用：

- `links: Array<{ type: 'story' | 'task'; id: number; text: string }>`

普通字段仍只使用 `label` 和 `value`。Webview 渲染时仅对有合法 `linkType` / `linkId` 或 `links` 的字段生成内部链接。

### 相关研发需求

任务详情页的 `相关研发需求` 从原始响应中提取故事 ID 和标题：

- ID 优先字段：`storyID`、`storyId`、`story` 中的对象 ID。
- 标题优先字段：`storyTitle`、`storyName`、`story.title`、`story.name`。
- 有合法 ID 时渲染为可点击链接，点击后打开对应需求详情。
- 无合法 ID 时保持纯文本展示。

### 关联任务

需求详情页新增或渲染 `关联任务` 字段，数据从原始响应中的任务列表类字段提取：

- 优先识别 `tasks`、`linkedTasks`、`children` 等数组或对象列表。
- 每个任务提取 ID 与名称，渲染为多个可点击任务链接。
- 无关联任务时显示 `暂无`。

## 页内文本匹配

Webview 内拦截 `Ctrl+F` 和 `Cmd+F`：

- 显示一个轻量搜索框，不调用浏览器默认查找。
- 输入关键词后在详情页可见文本中高亮匹配。
- `Enter` 跳转到下一处匹配，`Shift+Enter` 跳转到上一处匹配。
- `Escape` 关闭搜索框并清除高亮。

搜索只处理当前 Webview DOM 中的文本节点，不改动富文本源数据，不搜索隐藏的脚本内容。

## 附件模块

### 表格显示

附件表增加列：

- `文件名`：保持现有点击下载行为。
- `大小`：统一显示为 `K`。
- `预览`：显示文本固定为 `预览`。

附件大小规则：

- 字节数字按 `size / 1024` 转为 `K`。
- 已是 `K` / `KB` 的值归一为 `K`。
- 已是 `M` / `MB` 的值换算为 `K`。
- 无法解析时保持原值；空值显示 `暂无`。

### 预览面板

点击 `预览` 后，Webview 发送 `previewAttachment` 消息，`detailPanel.ts` 校验索引后新建 VS Code Webview 面板。

预览面板展示：

- 附件名称。
- 文件大小。
- 添加时间。
- 可用下载 URL 或文件 ID。
- 原始附件字段的脱敏 JSON。

预览面板不执行远程脚本，不直接渲染不可信附件内容；后续如果要支持图片或 PDF 原文预览，需要单独设计安全策略。

## 安全设计

- 继续使用 Webview CSP 和 nonce。
- 禅道富文本仍通过 `sanitize-html` 清洗。
- 内部链接只允许固定消息类型：`openDetail` 和 `previewAttachment`。
- Webview 消息必须校验类型、索引、对象类型和 ID。
- 附件预览面板只展示转义后的文本和脱敏 JSON。
- 不把 token、password、cookie 写入详情 HTML 或预览 HTML。

## 测试策略

先补失败测试，再实现：

1. `detailMapper.test.ts`
   - 进度 `17` 显示为 `17%`，`17%` 不重复追加。
   - 工时字段 `1` 显示为 `1h`，`1h` 和 `1工时` 保持不变。
   - 日期时间格式化为 `yyyy-mm-dd hh:mm:ss`。
   - 附件大小换算为 `K`。
   - `相关研发需求` 和 `关联任务` 生成合法内部链接模型。
2. `html.test.ts`
   - 基础字段链接渲染为内部链接数据属性。
   - 附件表包含 `预览` 列和 `previewAttachment` 消息。
   - HTML 包含页内搜索 UI 与 `Ctrl+F` 处理逻辑。
3. `detailPanel.test.ts`
   - `openDetail` 消息打开对应需求或任务详情。
   - `previewAttachment` 消息创建附件预览面板。
   - 非法消息、非法索引和非法 ID 被忽略。
4. 全量验证：`npm run verify`。

## 验收标准

- 任务进度不会出现缺失 `%` 或重复 `%%`。
- 工时字段不会出现缺失单位或重复追加单位。
- 日期时间字段以 `yyyy-mm-dd hh:mm:ss` 展示。
- 点击 `相关研发需求` 能打开需求详情页。
- 点击 `关联任务` 能打开任务详情页。
- 在详情页按 `Ctrl+F` / `Cmd+F` 可以搜索并高亮文本。
- 附件大小显示为 `K`。
- 点击附件 `预览` 会在 VS Code 内新开预览面板。
- 现有附件下载、图片预览、Markdown 导出功能不回退。
