# 附件添加时间列设计

## 背景

当前禅道 VS Code 扩展的详情页会展示需求/任务详情、附件列表、附件预览入口，并支持将详情导出为 Markdown。附件数据在详情映射层已经包含 `addedDate` 字段，来源于禅道返回的 `addedDate`、`addedTime`、`date` 或 `openedDate` 等字段，并经过日期时间格式归一化。

现有问题是：详情页附件表和 Markdown 导出附件表只展示文件名、大小等信息，没有把已有的附件添加时间展示出来。用户希望在详情页下的附件模块新增一列显示附件添加时间，并且导出的 Markdown 也保持一致。

## 目标

- 在详情页附件表中新增“添加时间”列。
- 在 Markdown 导出的附件表中同步新增“添加时间”列。
- 复用现有 `AttachmentViewModel.addedDate` 数据，不新增禅道 API 请求，不改变附件下载和预览交互。
- 保持现有安全边界：详情页 HTML 继续转义纯文本，Webview 消息与附件预览逻辑不因本次改动扩大权限或输入面。

## 非目标

- 不调整禅道 API 请求路径或认证流程。
- 不新增附件上传、删除、重命名等写操作。
- 不重构附件预览、附件下载、图片预览或详情页整体布局。
- 不扩展其它模块的附件展示入口，除非它们复用详情页或 Markdown 导出的同一渲染路径。

## 推荐方案

采用最小闭环改动：只在展示层和导出层消费已有的 `attachment.addedDate`。

候选方案中，未选择“增强字段兜底”是因为当前映射层已经覆盖 `addedDate`、`addedTime`、`date`、`openedDate`，足以支撑本次需求；未选择“附件模块整体重构”是因为本次需求只是新增一列，重构会扩大风险和验证成本。

## 详情页设计

当前详情页附件表保留原有交互语义：

- 文件名列：点击后下载附件。
- 大小列：显示归一化后的附件大小。
- 预览列：点击后打开附件预览。

本次在“大小”和“预览”之间新增“添加时间”列，表头调整为：

| 文件名 | 大小 | 添加时间 | 预览 |
| --- | --- | --- | --- |
| spec.docx | 15.11K | 2026-05-21 10:18:00 | 预览 |

这样新增信息不会改变文件名下载入口，也不会改变最后一列预览入口的位置含义。

当 `attachment.addedDate` 缺失或映射层无法识别时间时，继续显示映射层当前兜底值（例如 `未知`），避免空白单元格和渲染中断。

## Markdown 导出设计

Markdown 导出的附件表与详情页保持信息一致，但不包含“预览”列，因为导出文件中没有插件内预览交互。表头调整为：

| 文件名 | 大小 | 添加时间 |
| --- | --- | --- |
| spec.docx | 15.11K | 2026-05-21 10:18:00 |

文件名仍按现有逻辑保留链接：如果附件存在 URL，则导出为 Markdown 链接；否则导出纯文本文件名。大小和添加时间都使用表格单元格转义逻辑，避免文件名或时间文本中的特殊字符破坏 Markdown 表格。

## 数据流

本次不改变数据流，只补齐最终展示：

1. `detailPanel` 打开需求/任务详情并获取原始禅道响应。
2. `detailMapper` 将原始附件数组映射为 `AttachmentViewModel[]`。
3. `AttachmentViewModel.addedDate` 已由 `dateTimeValue` 归一化。
4. `html.renderDetailHtml` 渲染详情页附件表，并新增“添加时间”列。
5. `markdownExport.detailToMarkdown` 导出附件表，并新增“添加时间”列。

## 错误处理与兼容性

- 若没有附件，详情页仍显示“暂无附件”，Markdown 仍显示“暂无附件”。
- 若附件添加时间未知，显示 `attachment.addedDate` 当前值；映射层已有默认 `未知`。
- 本次不引入异步操作，不会改变请求失败、详情加载失败、附件下载失败或预览失败的处理路径。
- Webview CSP、nonce 脚本、HTML 转义和富文本清洗策略保持不变。

## 验收标准

- 详情页有附件时，附件表显示“文件名 / 大小 / 添加时间 / 预览”。
- 详情页无附件时，仍显示“暂无附件”。
- Markdown 导出有附件时，附件表显示“文件名 / 大小 / 添加时间”。
- Markdown 导出无附件时，仍显示“暂无附件”。
- 附件下载和附件预览入口行为不变。
- 单元测试和项目验证命令通过。
