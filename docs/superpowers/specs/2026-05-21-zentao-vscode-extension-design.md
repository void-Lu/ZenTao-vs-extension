# 禅道 VS Code 查询扩展设计

## 背景与目标

当前工作区为空，目标是开发一个 VS Code 扩展，基于禅道 v18.x API v1 查询指定项目下的需求、任务列表和详情。一期只实现查询与展示，不实现新增、修改、删除、状态流转等写操作，但保留后续扩展边界。

已参考公开项目 `easysoft/zentao-vscode-integration`：该扩展更偏向从 VS Code 跳转到禅道页面和生成 Commit Message。本扩展的一期方向不同，重点是在 VS Code 内结构化浏览项目需求、任务和详情。

## 范围

### 一期包含

- 用户配置禅道地址和项目号。
- 用户输入禅道用户名、密码，通过 API 获取 token。
- 查询指定项目详情。
- 查询指定项目下的需求列表。
- 查询指定项目的执行列表，并汇总执行下的任务列表。
- 查询需求和任务详情。
- 在 VS Code 侧边栏展示项目、需求、任务树。
- 在 Webview 中展示结构化详情 HTML。
- 展示附件，并提供插件内下载入口。
- 展示评论 / 操作历史。
- 展示完整原始响应 JSON，便于排查字段和后续扩展。
- 提供重新连接和请求日志入口。

### 一期不包含

- 新增需求或任务。
- 修改需求或任务。
- 删除需求或任务。
- 需求或任务状态流转。
- 禅道 Bug、产品、测试、文档等其他模块的完整管理。
- 多项目切换。项目号一期固定在工作区配置中。

## 配置与凭据

### 工作区配置

工作区 settings 保存非敏感配置：

- `zentao.baseUrl`：禅道基础地址。
- `zentao.projectId`：当前工作区绑定的禅道项目号。
- `zentao.requestTimeout`：请求超时时间。

`baseUrl` 只允许 `http` 或 `https`，保存时统一规范为带尾部 `/` 的形式。

### SecretStorage

使用 VS Code `SecretStorage` 保存敏感信息：

- 用户名。
- 密码。
- token。

不在 settings、请求日志、Webview HTML、错误消息中输出密码或 token。

## VS Code 交互设计

### Activity Bar / 侧边栏

贡献一个禅道视图容器，视图标题为“禅道项目”。标题右侧提供两个小按钮：

- `重新连接`：使用 SecretStorage 中的账号和密码重新获取 token；若凭据不存在或认证失败，提示用户重新输入。
- `请求日志`：打开禅道请求日志输出面板。

### TreeView 结构

树结构：

```text
禅道项目                          [重新连接] [请求日志]
└─ 企业管理系统                    项目号 #123
   ├─ 需求                         共 32 条
   │  ├─ #101 登录优化              P1 active
   │  └─ #102 报表导出              P2 changed
   └─ 任务                         共 58 条
      ├─ #201 前端页面              P1 wait
      └─ #202 API 联调              P2 doing
```

列表项展示字段：

- ID。
- 名称。
- 优先级。
- 状态。

树项操作：

- 点击或回车：打开详情。
- 右键菜单：复制编号、在浏览器中打开禅道页面。
- 分组刷新：重新请求该分组数据。

### Detail Webview

需求和任务详情使用同一个 Webview 面板。打开新条目时复用已有面板并刷新内容。

详情页布局顺序：

1. 标题：`#ID 名称`。
2. 基础信息紧凑列表：
   - 项目。
   - 产品。
   - 状态。
   - 优先级。
   - 指派。
   - 版本。
3. 描述 / 验收标准：页面重点区域，展示清洗后的禅道富文本。
4. 附件：显示附件名称、添加日期、下载入口。
5. 评论 / 操作历史：显示时间、操作者、评论内容、动作描述。
6. 完整原始响应：折叠 JSON。

基础字段应缩小行间距，避免挤占描述、验收标准和评论区域。

## API 设计

### 认证

获取 token：

```http
POST /api.php/v1/tokens
Content-Type: application/json

{ "account": "...", "password": "..." }
```

成功后保存返回的 `token`。后续请求通过 `Token` 请求头发送。

### 刷新树数据

刷新树视图时按顺序请求：

1. `GET /api.php/v1/projects/{projectId}`：获取项目详情。
2. `GET /api.php/v1/projects/{projectId}/stories`：获取项目需求列表。
3. `GET /api.php/v1/projects/{projectId}/executions`：获取项目执行列表。
4. 对每个执行请求 `GET /api.php/v1/executions/{executionId}/tasks`：获取执行任务列表。
5. 合并任务列表，映射为 TreeView 节点。

分页接口先请求第一页。如果响应包含 `page`、`total`、`limit`，且 `total > limit`，再用 `limit=total` 拉取全量数据。

### 打开详情

- 需求详情：`GET /api.php/v1/stories/{storyId}`。
- 任务详情：`GET /api.php/v1/tasks/{taskId}`。

详情响应保留完整原始 JSON，同时抽取用于 UI 展示的字段。

### 附件下载

详情页从 `files`、`storyFiles` 等字段抽取附件。附件展示字段：

- 文件名。
- 文件大小（如果接口返回）。
- 添加日期（如果接口返回）。
- 下载按钮。

添加日期优先从附件对象的日期字段读取；如果没有日期字段，显示“添加日期：未知”。

下载命令通过隔离的 `downloadAttachment(file)` 适配器实现。适配器按以下顺序处理：

1. 如果附件对象提供可下载 URL，使用该 URL 并带 token 请求。
2. 如果附件对象只提供文件 ID，调用禅道 v1 文件接口下载。
3. 如果当前实例响应格式无法判断下载地址，提示“当前附件缺少可下载地址”，并在原始 JSON 中保留字段供排查。

### 评论 / 操作历史

从详情响应中抽取评论和动作记录。优先字段：

- `actions`。
- `actions[].comment`。
- `actions[].desc`。
- `actions[].history`。
- 其他响应中同义的评论字段。

展示顺序按时间升序或接口返回顺序；如果无数据，显示“暂无评论 / 操作历史”。

## 数据模型

### 树节点模型

统一树节点字段：

- `id`。
- `type`：`project`、`storyGroup`、`taskGroup`、`story`、`task`。
- `title`。
- `priority`。
- `status`。
- `raw`：原始列表项。

### 详情模型

统一详情字段：

- `id`。
- `type`：`story` 或 `task`。
- `title`。
- `basicFields`：项目、产品、状态、优先级、指派、版本。
- `descriptionHtml`。
- `acceptanceHtml`。
- `attachments`。
- `activities`。
- `raw`：完整原始响应。

## 请求日志

“请求日志”按钮打开 VS Code 输出面板。日志记录：

- 时间。
- HTTP 方法。
- API 路径。
- 状态码。
- 耗时。
- 错误摘要。

日志必须脱敏：

- 不记录密码。
- 不记录 token。
- 不记录 Cookie。
- 不记录完整敏感请求体。

## 错误处理

- 未配置 URL 或项目号：TreeView 显示引导项，提示打开设置。
- 未登录：TreeView 显示登录引导项。
- 401：清理 token，保留 URL、项目号、用户名和密码，提示重新连接。
- 403：提示当前账号无权限访问项目或对象。
- 404：提示项目、需求或任务不存在，或已删除。
- 网络错误 / 超时：显示重试入口，并写入请求日志。
- 部分执行任务拉取失败：保留已成功数据，在任务分组显示部分失败提示。

## 安全设计

- 使用 `SecretStorage` 保存用户名、密码和 token。
- Webview 使用 CSP 和 nonce。
- 禅道富文本先经过白名单清洗再渲染。
- HTML 中不注入未转义的 JSON 字符串。
- 请求日志脱敏敏感字段。
- 附件下载由插件命令处理，不允许 Webview 任意访问本地文件。
- `baseUrl` 只允许 `http` 和 `https`。

## 后续写操作预留

一期只实现查询接口。代码结构上保留后续扩展点：

- `ZenTaoClient` 按资源分组，后续可添加 `updateStory`、`deleteStory`、`updateTask`、`deleteTask` 等方法。
- 命令注册按只读命令和写操作命令分组。
- 写操作必须单独增加确认流程、权限错误处理和测试，不混入当前查询渲染逻辑。

### 扩展集成测试

### 手动验证

- 首次配置 URL 和项目号。

- 重新连接。
- 树视图展示项目号、需求总数、任务总数。

## 验收标准

- 用户能在工作区配置禅道 URL 和项目号。
- 用户能登录并获取 token。
- 侧边栏能显示项目、需求分组和任务分组。
- 需求/任务分组显示实际获取总数。
- 需求/任务条目显示 ID、名称、优先级、状态。
- 点击需求或任务能打开结构化详情页。
- 详情页基础字段按项目、产品、状态、优先级、指派、版本展示。
- 详情页重点展示描述 / 验收标准。
- 附件位于评论 / 操作历史上方。
- 附件能显示添加日期或“未知”。
- 评论 / 操作历史能从响应中抽取并展示，缺失时显示空状态。
- 请求日志可打开且敏感字段已脱敏。
- 富文本经白名单清洗后渲染。
- 一期没有新增、修改、删除、状态流转入口。
