# 禅道列表分页/分批加载方案

## Summary

保留当前需求/任务列表获取逻辑，只通过分页/分批降低大列表超时风险。

需求列表有多个来源，只有所有给定来源都无法获取可用需求时才算失败。任务列表只按执行获取，但无执行、有执行无任务、需求无任务都属于正常业务状态，不报错。

## Key Changes

- `ZenTaoClient.getAll()` 从 `limit=total` 改为固定分页聚合：每页 50 条，按 `page=1,2,...` 顺序请求，直到已获取数量覆盖 `total`。
- 已有查询参数的接口正确追加分页参数，例如 `stories?product=169&limit=50&page=1`。
- 保留当前需求获取路径：项目需求、产品需求、执行需求；中间来源失败但其他来源成功获取到可用需求数据时，不标记需求失败。
- 去除任务关联 story ID 缺失后的逐条补拉策略；默认不会出现“有任务无需求”的有效状态。
- 保留任务获取路径：按执行拉任务列表，跨执行请求继续受 `settleWithConcurrency = 5` 限制。
- 刷新时重新拉取分页后的需求/任务列表；所有已打开的需求/任务详情页都需要刷新。

## Failure Semantics

- 需求：所有需求列表来源都失败，且无法得到任何可用需求数据时，才标记需求失败。
- 需求：有需求但没有任务是正常状态，不报错。
- 任务：无执行时任务为空，不报错。
- 任务：有执行但所有执行都成功返回空任务列表，不报错。
- 任务：任一执行任务请求失败，标记任务部分失败；全部执行任务请求失败时也属于任务失败。
- 请求失败仍记录到请求日志，用于排查。

## Test Plan

- `zentaoClient`：分页超过 50 条时按页请求并合并 `stories/tasks/executions/projects`。
- `zentaoClient`：带查询参数的路径分页 URL 正确。
- `loadProjectData`：部分需求来源失败但其他来源成功时，不设置需求失败提示。
- `loadProjectData`：所有需求来源失败时，才标记需求失败。
- `loadProjectData`：无执行时不标记任务失败。
- `loadProjectData`：有执行但任务列表全为空时，不标记任务失败。
- `loadProjectData`：任一执行任务请求失败时，标记任务部分失败。
- `extension`：刷新列表后，会刷新所有已打开的详情页。

## Assumptions

- 不新增用户配置；分页大小固定为 50。
- 禅道分页参数沿用当前接口返回字段语义：`page`、`limit`、`total`。
- 本文档仅记录实现计划，不修改源码。
